# 의사결정·시행착오 기록 (2026-09-08 ~ 09-09)

시간순. 각 항목은 "무엇을 결정했고, 왜, 무엇이 틀렸었나". 수치의 출처는 8_train/README.md·PLAN.md·보고서 PDF.

## 1. 학습 환경
- **결정** 학습은 ssh 서버의 격리 Docker 컨테이너에서, Claude Code Remote Control로 세션 간 위임. GPU 1장 고정, RAM 48g, 포트 없음, 마운트는 프로젝트 폴더 하나(`docker/`).
- **시행착오** ① NGC 25.06(CUDA 12.9)은 드라이버 535(GeForce)에서 안 떠 CUDA 12.1 이미지로 교체. ② named volume이 root 소유로 생겨 로그인 실패 → 이미지에서 agent 소유 디렉터리를 미리 생성. ③ compose 프로젝트명이 폴더명 `docker`라 다른 스택(weak-support)의 orphan으로 잡힘 → `name: form-model` 고정. ④ 학습 중 GPU 채점 OOM(21.7/24.5GB) → 채점은 CPU, score.py에 `--chunk`.

## 2. 1차 학습 (clean 20,000, 6 epoch)
- **결정** VLM보다 검출기(FFDNet-L, YOLO11) 먼저. imgsz 1600, batch 4(8은 OOM).
- **결과** 홀드아웃 3축 통과(99.97%), 실서식 66.6%, stress 55.0%.
- **틀렸던 판단** 1 에폭 때 "덜 배워서"로 봤으나 5 에폭에 실서식이 오히려 하락 → 합성 과적합. 홀드아웃만 보고 진행 판단한 것이 근본 원인 → 이후 실서식·stress를 에폭마다 채점.
- **진단** conf 스윕(문턱 아님), 놓침 해부(96.4% 진짜 미검출, 규약 불일치 아님), 스타일별 recall(생성기 주력 cg 1.96%, 처음 보는 마커 98~100%) → "구성의 부재가 아니라 치수·문맥 분포 밖".

## 3. 2차 학습 (+증강 62,000, 1 epoch에서 R1 자동 종료)
- **결정** 자원 낭비 방지 규칙 R1~R5(목표 달성·망각·조기 실패·정체·상한)를 컨테이너가 자율 판정.
- **결과** stress 55.0→99.94, 홀드아웃 유지, 실서식 66.6→59.6.
- **틀렸던 판단** 스타일 진단 뒤 "픽셀 증강은 무관"으로 일반화 → stress 채점으로 뒤집힘. 두 축(픽셀·레이아웃)은 독립이 아니고 열화 적응의 비용을 넓은 셀(cgf −21.9pt)이 치렀다.

## 4. 아키텍처: 찾기(1단계)와 판단(2단계) 분리
- **근거** radio 176 중 106을 checkbox로(같은 □ 글리프, 문맥으로만 구분). P1.5 프로브: VLM은 "몇 개"는 100%, "어디"는 0%. 문헌: ChatRex·AcroMELD·Hallucination-Free GUI·CommonForms 3종 축소·CheckboxQA 경고.
- **결정** 1단계 클래스는 생김새 기준 8종. 판정 기준 K1 분리 가능·K2 박스 규약 동질·K3 배경과 대비·K4 표본 충분·K5 하류 유용.
- **클래스별 판정** marker(K3: 인쇄 □ 글머리만 혼동) · comb(마커와 run 여부로 구분, 2개 이상) · cell(K2 위반 → 셀 안쪽 통일, 라벨 인쇄 셀은 요소 박스) · gap(K3 약함 → 문맥 다양성으로 보완) · underline · placeholder(K3 약함, 고정 글리프 의존) · signature(문구·직인만, 서명용 빈 셀은 cell) · photo(cell에 넣으면 cell의 "비어 있음"이 깨짐 → 독립, K4 부족은 생성기로) · **기각** word(K3 위반: 인쇄 단어와 같음 → 2단계 OCR) · area(K1·K3 위반 → 구조 후보).
- **검토판 시행착오** v1~v9. 잘못된 예시 5건 중 규칙 버그 1건(○를 글리프로), 나머지 4건은 복제본 데이터 결함.

## 6. 데이터 재구성 원칙
- **균일 분포 기각** photo 5% = 페이지마다 사진 5개 → 문맥 파괴. 보충은 문맥을 되돌리지 못하고 이미 100%인 comb에 예산을 낭비.
- **채택** 자연 분포 + 클래스 하한(RFS, build_skeleton IRFS) + 측정된 실패에만 보충 + 부족 클래스는 **그 클래스를 논리적으로 요구하는 서식 유형**(사진대지·서명부·진술서·작성례)으로. 근거: CommonForms(자연 분포에서 드문 Signature가 최고 AP), DocSynth-300K(다양성 최적화), LMM-Det·SAHI(약한 조건 노출 확대), Beyond Human Annotation(다양성·효용으로 평가).
- **P0 측정** 학습 cell 64만 개 전부 높이 ≤30px; 표 안 gap·underline·소형 signature·comb·[ ] 마커 0. → 격자(클래스 × 폭 × 높이 × 문맥) 커버리지가 기준.

## 9. 3차 학습 진행 (2026-09-10)
- **e1** 실서식 후보 recall(0.05) 83.85, 좌표 96.22·종류 97.17 **첫 통과**, stress 99.88, 홀드아웃 99.77. 8종 분리의 효과가 종류 축(58.6→97.2)에 가장 크게. cell 2차 45→83.
- **e2** 실서식 81.38(−2.47, 거의 전부 cell −7.1), 합성은 계속 상승 → 2차와 같은 "합성에 맞춰지며 실서식 보수화" 패턴. 좌표·종류는 기준 유지. e1 이 최고점, R4 판정은 e3.
- **진단(e1, CPU)** 남은 실패는 전부 작고 낮은 요소: 놓친 gap 75 중 69가 높이 ≤20, 놓친 cell 56 중 48이 폭 ≤200·높이 ≤45. 크롭 대조로 원인 특정:
  1. 놓친 cell 26 중 25가 **글자가 인쇄된 척도표 선택칸**(매우만족·만족·보통…). 학습엔 글자 든 선택칸이 사실상 없음.
  2. 놓친 gap 은 "년/월/일/./~" 사이 **10~20px 밀착 슬롯**. 학습은 24~44px 에 여백 있음. **폭 ≤20 gap 은 학습 0개**(실서식 20개).
  3. 실서식 소형 셀은 괘선 한두 변·회색 머리행에 붙음, 학습은 사방 괘선·흰 배경.
- **정정** "격자 칸이 차 있으니 개수 문제 아님"은 버킷이 거칠어서였음. 더 잘게 나누면 빈 구간(gap w≤20)이 있고 비중 불일치(gap 40~60: 실서식 44% vs 학습 14%, cell 폭 70 vs 107)가 있음.
- **다음 생성기 보강 우선순위** ① 글자 인쇄 척도 선택칸 ② gap 폭 10~20px 밀착 슬롯 ③ gap 40~60px 비중 ④ cell 폭 60~90 비중.
- 도구: diag_style 이 word·area 페이지 3장(113칸)을 건너뛰던 문제 → to_yolo 와 같은 규칙으로 정렬(`--gt-dir`), 전수 972 로 score.py 와 일치.
- **e3 R4 종료, e1 채택** (실서식 83.85 / 좌표 96.22 / 종류 97.17 / stress 99.88 / 홀드아웃 99.96). 가중치 선택 기준을 "1차 지표(실서식 recall@0.05) 최고점"으로 명시(val 기준 best.pt 는 e3 로 실서식 3.2pt 낮음). 1차 대비 스타일 16종 중 15종 개선·유지, 하락은 ck −0.95(1개) 뿐. 비교 기준선은 GT 정정 후(999) 파일을 써야 함(정정 전 954 와 비교하면 착시).
