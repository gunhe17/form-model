# 의사결정·시행착오 기록 (2026-09-08 ~ 09-09)

## 1. 학습 환경
- **결정** 학습은 ssh 서버의 격리 Docker 컨테이너에서, Claude Code Remote Control로 세션 간 위임. GPU 1장 고정, RAM 48g, 포트 없음, 마운트는 프로젝트 폴더 하나(`docker/`).
- **시행착오** ① NGC 25.06(CUDA 12.9)은 드라이버 535(GeForce)에서 안 떠 CUDA 12.1 이미지로 교체. ② named volume이 root 소유로 생겨 로그인 실패 → 이미지에서 agent 소유 디렉터리를 미리 생성. ③ compose 프로젝트명이 폴더명 `docker`라 다른 스택(weak-support)의 orphan으로 잡힘 → `name: form-model` 고정. ④ 학습 중 GPU 채점 OOM(21.7/24.5GB) → 채점은 CPU, score.py에 `--chunk`.

## 2. 1차 학습 (clean 20,000, 6 epoch)
- **결정** VLM보다 검출기(FFDNet-L, YOLO11) 먼저. imgsz 1600, batch 4(8은 OOM).
- **결과** 홀드아웃 3축 통과(99.97%), 실서식 66.6%, stress 55.0%.
- **틀렸던 판단** 1 에폭 때 "덜 배워서"로 봤으나 5 에폭에 실서식이 오히려 하락 → 합성 과적합. 홀드아웃만 보고 진행 판단한 것이 근본 원인 → 이후 실서식·stress를 에폭마다 채점.
- **진단** conf 스윕(문턱 아님), 놓침 해부(96.4% 진짜 미검출, 규약 불일치 아님), 스타일별 recall(생성기 주력 cg 1.96%, 처음 보는 마커 98~100%) → "구성의 부재가 아니라 치수·문맥 분포 밖".

## 3. 2차 학습 (+증강 62,000, 1 epoch에서 R1 자동 종료)
- **결정** 자원 낭비 방지 규칙 R1~R5(목표 달성·망각·조기 실패·정체·상한)를 컨테이너가 자율 판정.
- **결과** stress 55.0→99.94, 홀드아웃 유지, 실서식 66.6→59.6.
- **틀렸던 판단** 스타일 진단 뒤 "픽셀 증강은 무관"으로 일반화 → stress 채점으로 뒤집힘. 두 축(픽셀·레이아웃)은 독립이 아니고 열화 적응의 비용을 넓은 셀(cgf −21.9pt)이 치렀다.

## 6. 데이터 재구성 원칙
- **균일 분포 기각** photo 5% = 페이지마다 사진 5개 → 문맥 파괴. 보충은 문맥을 되돌리지 못하고 이미 100%인 comb에 예산을 낭비.
- **채택** 자연 분포 + 클래스 하한(RFS, build_skeleton IRFS) + 측정된 실패에만 보충 + 부족 클래스는 **그 클래스를 논리적으로 요구하는 서식 유형**(사진대지·서명부·진술서·작성례)으로. 근거: CommonForms(자연 분포에서 드문 Signature가 최고 AP), DocSynth-300K(다양성 최적화), LMM-Det·SAHI(약한 조건 노출 확대), Beyond Human Annotation(다양성·효용으로 평가).
- **P0 측정** 학습 cell 64만 개 전부 높이 ≤30px; 표 안 gap·underline·소형 signature·comb·[ ] 마커 0. → 격자(클래스 × 폭 × 높이 × 문맥) 커버리지가 기준.

## 9. 3차 학습 진행 (2026-09-10)
- **e1** 실서식 후보 recall(0.05) 83.85, 좌표 96.22·종류 97.17 **첫 통과**, stress 99.88, 홀드아웃 99.77. 8종 분리의 효과가 종류 축(58.6→97.2)에 가장 크게. cell 2차 45→83.
- **e2** 실서식 81.38(−2.47, 거의 전부 cell −7.1), 합성은 계속 상승 → 2차와 같은 "합성에 맞춰지며 실서식 보수화" 패턴. 좌표·종류는 기준 유지. e1 이 최고점, R4 판정은 e3.
- **진단(e1, CPU)** 남은 실패는 전부 작고 낮은 요소: 놓친 gap 75 중 69가 높이 ≤20, 놓친 cell 56 중 48이 폭 ≤200·높이 ≤45. 크롭 대조로 원인 특정:
  1. 놓친 cell 26 중 25가 **글자가 인쇄된 척도표 선택칸**(매우만족·만족·보통…). 학습엔 글자 든 선택칸이 사실상 없음.
  2. 놓친 gap 은 "년/월/일/./~" 사이 **10~20px 밀착 슬롯**. 학습은 24~44px 에 여백 있음. **폭 ≤20 gap 은 학습 0개**(실서식 20개).
  3. 실서식 소형 셀은 괘선 한두 변·회색 머리행에 붙음, 학습은 사방 괘선·흰 배경.
- **정정** "격자 칸이 차 있으니 개수 문제 아님"은 버킷이 거칠어서였음. 더 잘게 나누면 빈 구간(gap w≤20)이 있고 비중 불일치(gap 40~60: 실서식 44% vs 학습 14%, cell 폭 70 vs 107)가 있음.
- **다음 생성기 보강 우선순위** ① 글자 인쇄 척도 선택칸 ② gap 폭 10~20px 밀착 슬롯 ③ gap 40~60px 비중 ④ cell 폭 60~90 비중.
- 도구: diag_style 이 word·area 페이지 3장(113칸)을 건너뛰던 문제 → to_yolo 와 같은 규칙으로 정렬(`--gt-dir`), 전수 972 로 score.py 와 일치.
- **e3 R4 종료, e1 채택** (실서식 83.85 / 좌표 96.22 / 종류 97.17 / stress 99.88 / 홀드아웃 99.96). 가중치 선택 기준을 "1차 지표(실서식 recall@0.05) 최고점"으로 명시(val 기준 best.pt 는 e3 로 실서식 3.2pt 낮음). 1차 대비 스타일 16종 중 15종 개선·유지, 하락은 ck −0.95(1개) 뿐. 비교 기준선은 GT 정정 후(999) 파일을 써야 함(정정 전 954 와 비교하면 착시).

## 10. 3차 정밀 분석 → 4차 계획 (2026-09-10)
- **도구**: 컨테이너가 GT 단위 매칭 덤프(miss_dump_*.json, 컨테이너 로컬 커밋만 — push 자격증명 없음, 넣지 않기로 함)를 만들고, `8_train/diag_dump.py` 가 복제본 마크업으로 놓침을 원인별 귀속. 요약 출력만 세션 간 메시지로 전달.
- **정정 1**: "글자 인쇄 척도 선택칸은 학습에 없다"는 틀렸다. scale_words 카드가 296장 있으나 **보이지 않는 22px MKC 표식을 박스로 라벨**해 픽셀 근거가 없다(radio_likert·cb_matrix 포함 20k 중 약 2.1만 개). 실서식은 셀 전체. 원인은 부재가 아니라 **규약 불일치**. 1차·3차 모두 25/25 놓침, 변화 0.
- **정정 2**: "gap 폭 ≤20 밀착 슬롯"은 실서식 20개 중 18개가 1편 2호 한 장. 여전히 보강하되 우선순위는 B2(높이 ≤18, 32개)가 위.
- **새 원인 G**: 셀 왼쪽 라벨 + 오른쪽 잔여 입력(가로 inset, cg h26) 14개 전멸. 생성기 inset 카드는 세로형뿐.
- **새 원인 S**: 표 셀 안 빈 공간 뒤 (인) 소형 7개 전멸. 학습 (인) 은 문장 줄 끝에만.
- **e1→e3 하락**은 셀 37개 회복/5개 상실로 셀에 국한. MKC 충돌 감독 가설(PLAN 9.2), 4차에서 검증.
- **결정**: 4차는 생성기 보강 6항목(PLAN 9.4) 후 전면 재렌더·재학습. 임계값 0.05 유지. P5 앵커 확장 병행.
- 부동소수: 1차 실서식 recall 은 GPU 69.57 / CPU 69.37 (2칸). 이후 비교는 덤프(CPU) 기준.

## 16. P6-0 측정 도구 · 5차 학습 설정 구현 (2026-09-11)

문헌 조사(6_research/variation)를 실행 가능한 스크립트로 옮겼다. 순서 원칙은 **재는 도구 → 재는 대상 → 학습**이므로 GPU 없이 되는 것부터 만들었다.

**결정 1 — 실서식 수치에는 항상 CI 를 붙인다 (`diag_ci.py`).**
페이지를 군집으로 보고 **페이지 복원추출**(Field & Welsh 2007) 10,000회. 박스 단위 재표집은 분산을 과소추정한다. 두 모델 비교는 **같은 페이지 표본**으로 A−B 를 계산하는 짝지은 부트스트랩이라야 페이지 난이도 분산이 상쇄된다. 자가검증은 모집단 300쪽에서 44쪽을 300회 뽑아 CI 가 참값을 덮는 비율을 재는 방식 — 91.7%(명목 95%)로, 군집 수가 적을 때의 과소 커버리지까지 문헌대로 재현됐다. 출력은 결과표에 그대로 붙는 `89.20 [87.4, 91.1]` 한 줄.
- **틀렸던 판단**: 3차→4차 +6.6pt 를 점추정으로만 적었다. 44쪽에서 ±2pt 급 차이는 애초에 판별할 수 없으므로, 이후 결과표는 CI 없는 수치를 싣지 않는다.

**결정 2 — conf 는 격차 게이지이자 회수 가능성 점검 (`diag_conf.py`).**
합성/실 conf 분포의 AUROC 가 곧 "합성 특유 단서를 얼마나 외웠나"(Hendrycks 1610.02136). 검출 ECE 의 정답은 클래스가 아니라 **IoU≥0.5 매칭 여부**로 두었다. temperature 는 파라미터 1개라 실서식 소표본에 맞춰도 과적합 위험이 없다(Guo 1706.04599). T<1(저신)이면 임계값을 낮추는 것만으로 회수할 recall 이 있다는 뜻 — 생성기를 손대기 전에 0원으로 확인할 수 있다.
- 에너지(logsumexp) 지표는 **넣지 않았다.** 덤프에 로짓이 없어 예측 경로를 고쳐야 하는데, 4차에서 conf 만으로도 17배 차이가 이미 보였다. conf AUROC 가 포화되면 그때 추가한다.

**결정 3 — 커버리지는 crop 임베딩으로 (`diag_coverage.py`).**
recall 은 "못 찾았다"만 말하고 "무엇이 안 덮였나"는 말하지 않는다. GT 박스를 96×96 으로 리사이즈해 backbone(model.0~10) 통과 후 GAP — feature map 에서 박스 영역을 평균하는 쪽보다 구현이 단순하고 박스 크기 편차에 둔감하다. density/coverage(Naeem 2002.09797, k=5)와 코사인 커널 Vendi(Friedman & Dieng 2210.02410)를 numpy 만으로 구현(새 의존성 없음, CPU, 표본 상한 2,000이면 메모리 <1GB). 임베딩 차원 512 확인(YOLO11-L C2PSA 출력).

**결정 4 — 앵커 분할은 서식 단위, 전사 진행과 무관하게 지금 확정 (`4_replica/split_anchor.py`).**
같은 서식의 2·3쪽은 머리글·표 골격·어휘를 공유하므로 쪽 단위 분할은 템플릿 누수다. `1_corpus/page_manifest.json` **전량 157쪽 / 85서식**을 미리 갈라 `4_replica/split.json` 에 박았다 — 전사가 44 → 157 로 늘어도 분할은 바뀌지 않는다. seed=1 고정: 전체가 105/52(2:1)이면서 **현재 전사된 44장도 29/15** 로 갈린다(다른 seed 는 20/24 처럼 치우쳐 지금 당장 학습을 못 돌린다). 서식 겹침 0·페이지 겹침 0 은 스크립트가 assert 한다.
- PLAN 10절의 "149쪽 → 100/49" 는 코퍼스 실제 수(157쪽·85서식)와 다르다. **매니페스트를 정본으로 삼아 105/52** 로 간다.

**결정 5 — 5차 val 은 실서식 학습분 (`forms_s1v4.yaml`).**
Ultralytics 는 best.pt 와 patience 를 val fitness(0.1·mAP50 + 0.9·mAP50-95)로 고른다. val 이 합성이면 best.pt 는 **정의상 합성 최적점**이라 "e1 정점 후 실서식 하락"을 구조적으로 잡을 수 없다. 그래서 `val: images/replica_train`, `test: replica_eval + stress`. 실서식만으로 fitness 가 흔들리면 합성 홀드아웃과 1:1 로 섞는 대안을 yaml 에 주석으로 남겼다.

**결정 6 — 오버샘플은 코드가 아니라 목록으로 (`make_mix_list.py`).**
Ultralytics 는 data yaml 의 train 에 `.txt` 이미지 목록을 받고, 같은 경로가 여러 줄이면 그만큼 반복 등록한다(`data/base.py get_img_files` 확인). 실 5~20% 오버샘플도 합성 리플레이 20~30% 도 "목록에 몇 번 적을까"로 환원되므로 샘플러를 새로 쓰지 않았다. 라벨은 경로의 `/images/` → `/labels/` 치환으로 찾으므로 목록 경로에 `/images/` 가 있어야 한다.
