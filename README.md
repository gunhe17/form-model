# form-model-lab — image-to-form 을 자체 모델로 대체

빈 서식 이미지 → **FormSchema 좌표**를 한 모델이 통째로 낸다. 현행 `image-to-form` 의 ②대구획·③그라운딩·⑤carve 를 대체하는 것이 목표.

> 📄 **계획 전문**: [서식 좌표 모델 구축 계획](https://claude.ai/code/artifact/758cac16-6cc3-4d91-a400-e66b793fb956) — 10단계 절차·합격선·위험

## 구조 = 절차

폴더 번호가 곧 단계다. 각 단계는 앞 단계의 산출만 입력으로 받는다.

| 단계 | 폴더 | 내용 | 상태 |
|---|---|---|---|
| 0 원천 | `0_source/` | 사업안내 PDF 12부. 서식 pool 의 출처 + 향후 확장 후보 | 완료 |
| 1 코퍼스 | `1_corpus/` | 실서식 85종 157쪽 PNG(`pages/`), OCR 캐시 68쪽, 표집(probe·random·gap), 페이지 서지 | 완료 |
| 2 사양 | `2_spec/` | 코퍼스 분석의 결론: 부품 카드 79종(`pool.json`), 문서 문법 20유형(`doc_grammar.json`), 실측 치수 분포(`variation.json` 등) | 완료 (P0) |
| 3 생성기 | `3_generator/` | 사양 → 골격 JSON(`build_skeleton.py`) → HTML+PNG+GT(`render_skeleton.py`). 부품 정본은 `components.py`, HWP 질감은 `hwp_theme.py`, 전수 카탈로그는 `catalog/index.html` | 완료 (P2) |
| 4 복제 | `4_replica/` | 실서식을 손으로 충실히 옮긴 HTML 44쪽(`html/`)과 렌더·GT(`render/`). 학습 미포함 **평가 앵커** | 1차 44/149쪽 |
| 5 데이터셋 | `5_dataset/` | 골격(`skeletons/`) → 렌더(`train/` 20,000 · `holdout/` 996). 증강 전 확정본 | 완료 |
| 6 조사 | `6_research/` | 유사 사례·튜닝 문헌 97건(Opus 60 + Grok 37) 교차 검증. 좌표 0~1000 변환·detector 베이스라인 등 반영 항목 | 완료 |
| 7 증강 | `7_augment/` | 구분별 pool 확보: clean 20k · swap 6k(서체 재렌더) · office 26k · degraded 10k = 학습 62,000 + 평가용 stress 500. 기하는 YOLO 온라인 | 완료 |
| 8 학습 | `8_train/` | **검출기 트랙 먼저**: FFDNet-L(YOLO11) → 11클래스, imgsz 1600. 변환기·데이터 정의·스모크 완료, 본런은 3090×2 대기. 종류 미달 시 Qwen3-VL 분류 2단계 | 준비 완료 |

프로브(P1.5) 산출과 `probe_p15.py`·`gen_form.py`·`auto_label.py` 는 이 저장소에 없다(이전 작업공간 `form-model-lab`). 결과는 아래 "현재 단계" 표에만 남아 있다.

```bash
./venv/bin/pip install -r requirements.txt && ./venv/bin/playwright install chromium
./venv/bin/python 3_generator/build_skeleton.py --n 200 --out 5_dataset/skeletons/smoke   # 골격
./venv/bin/python 3_generator/render_skeleton.py 5_dataset/skeletons/smoke/*.json --out 5_dataset/smoke   # 렌더+GT
./venv/bin/python 3_generator/build_component_map.py            # 카탈로그 재생성
./venv/bin/python 4_replica/render_html.py 4_replica/html/*.html   # 복제 렌더
```

아래 작업 일지의 옛 경로: `pattern/` → `1_corpus/`·`2_spec/`, `runs/replica_*` → `4_replica/`, `runs/final_dataset`·`holdout_dataset`·`skeletons_*` → `5_dataset/`, `runs/component_map` → `3_generator/catalog/`. 일지에 나오는 그 밖의 `runs/*`(검증 스냅샷)는 보관하지 않았다.

## 왜

현행이 다섯 축 전부에서 미달이다. 재현성만의 문제가 아니다.

| 축 | 현행 | 근거 | 합격선 |
|---|---|---|---|
| 누락 | 최선의 방식도 서식2호 **86%** | `image-to-form/_verify/recall_lab` | ≥98% |
| 좌표 | 셀 경계 어긋남·옆 칸 침범 | carve 휴리스틱 한계 | IoU≥0.5 가 ≥95% |
| 타입 | 16종 오분류 | `recall_lab` consent 사례 | ≥97% |
| 밀집 붕괴 | 5회 실측 `54·16·56·57·16` (요약 모드) | `image-to-form/docs/DECISIONS.md` | ≥95% |
| 재현성 | 3회 반복 요소 수 ±3~4 | E40-b | 100% |

**전제**: 서식을 직접 생성하면 만드는 순간 정답을 안다. 문제지와 정답지가 동시에·무한히 나온다.

### 후속: 서식2호 인라인 □ 스트립 실험 (4B, □ 13개 스트립 × 배율 사다리)

| 배율 | ×1.0 | ×1.5 | ×2.0 | ×3.0 |
|---|---|---|---|---|
| 실제 □ 적중 | ~0 | 일부 | 유령 폭주 | **11/13 정확** |

**물리(해상도) 문제로 확정, 단 배율로 풀림.** 원본에선 스트립으로 줄여도 못 보고, ×3에선 글리프에 정확히 얹는다. 전체 페이지 ×3은 2.8만 토큰이라 불가 → P5에서 "학습이 임계 배율을 낮추는가"를 이 패턴으로 측정, 안 낮아지면 밀집 서식만 고배율 부분 처리. 생성기 사양 구체화: 글리프 ~15px급 인라인 □를 다양한 배율로 렌더. 재현: `runs/strip_s2_x*.png`
- **출력 계약 불신** — Qwen은 발산 시 절대 픽셀로 이탈, North Micro는 형식 통째 무시. 문법 강제가 필수. "빠짐없이 찾아라"는 지시 자체가 안 보일 때 유령을 지어내게 만드는 압박일 수 있음(프롬프트 성질, 학습 시 GT가 교정)

### 후속 2: 질문 방식을 바꾸면 (2026-09-02)

같은 이미지·같은 모델에 질문만 달리했다.

| 질문 | 배율 | 결과 |
|---|---|---|
| **"몇 개인가"** (순수 논리) | ×1.0 | **5행 전부 정답, 합계 13 정확, 3회 재현** ✅ |
| "어디인가" (좌표) | ×1.0 | 0% |
| "몇 번인가" (SoM, CV 후보 32개 중 고르기) | ×1.0 | 전부 거부 — 붕괴 |
| 〃 | ×2.0 | 29/32 수락 · 정밀도 62% ≈ 기저율 56%, 판별력 없음 |

**×1.0에서 위치는 0%인데 개수는 100%다.** 모델은 체크박스가 거기 있음을 안다 — 좌표로 표현하지 못할 뿐.
→ "안 보여서 못 찾는다"던 앞선 결론은 **틀렸다**. 보이는데 좌표 출력이 약점이다.
→ 단 SoM 필터링도 제로샷에서는 한쪽 쏠림으로 붕괴. "CV 후보 → 모델 선별" 구조는 학습 없이는 못 쓴다.

### 후속 3: CV는 어디까지 믿을 수 있나 (2026-09-02)

`region_segment` 셀·밴드 + 체크박스 글리프 검출을 합친 후보가 실제 요소와 **크기까지** 맞는 비율.
대상: `raw/*.json` 18서식 873요소. 서식당 후보 중앙 232개(최대 481).

| 잘됨 | | 중간 | | 안 됨 | |
|---|---|---|---|---|---|
| textarea | 100% | date | 59% | checkbox_group | 28% |
| image | 100% | phone | 56% | radio | **0%** |
| number | 96% | email | 50% | signature | **0%** |
| text | 87% | | | time | **0%** |

**합계 IoU≥0.5 기준 71%.** 표 칸 안 요소(전체의 64%)는 괘선으로 경계가 명확해 CV가 잘하고,
글줄 안에 박힌 요소(21%)는 경계 정의 자체가 없어 CV가 못 한다.

⚠ **두 단서 필수** — ⑴ 채점 기준이 LLM이 뽑은 좌표라 그 자체가 "대략치"(README 자인). CV가 아니라 기준이 틀린 경우가 섞여 있다. ⑵ checkbox 28%는 정의 불일치 가능성 — CV는 □ 글리프만, 기준은 `□+라벨` 전체를 잰다. 실제로 서식2호에서 진짜 체크박스 18개를 CV가 전부 후보에 포함시켰다(검출은 성공, 범위 정의가 다름).

**→ 아키텍처(좌표를 모델이 낼 것인가 CV가 낼 것인가) 확정은 P0 이후.** 정확한 좌표 정답 없이는 이 표의 숫자를 신뢰할 수 없다.


## 유형 확장: address (2026-09-03)

검수 중 결정 — `주소`를 `text` 에서 분리해 **`address`** 유형 신설 (한국 폼의 우편번호 검색 위젯 대응).
⚠ **FormSchema 16종 계약 밖**이다. 선택지: ⑴ 계약을 17종으로 확장 ⑵ 내보낼 때 `text` 로 정규화.
P0 완료 시점에 결정한다. 소급: 초안 12건 text→address.
