# 규약에 없던 패턴 · 전사 판단 기록

CONVENTIONS.md 의 클래스만으로 표현하기 어려웠거나, 판단이 필요했던 것들.
(P6-1 앵커 확장 44→100쪽 배치에서 기록)

## 1. 대각선 분할 머리칸 (번호/이름/날짜)
- 페이지: `1편_서식9호_교육대상자_출석부-1`, `3편_서식10호_언어발달지원_서비스_제공_기록지_(_월)-1`
- 원본: 표 좌상단 칸이 대각선 1~2줄로 3분할되고 각 구획에 라벨이 있음.
- 처리: `td` 안에 `<svg>` 로 대각선을 긋고 라벨을 `position:absolute` 로 배치 (`.diag`).
  data-f 없음(인쇄 라벨).

## 2. 이중 괘선(=)으로 나뉘는 블록 표
- 페이지: `1편_서식1호_사회보장급여_신청(변경)서-1~4`, `1편_서식24호-16~23`
- 원본: 표에 좌·우 외곽 세로선이 아예 없고, 블록 경계만 이중 가로줄.
- 처리: 블록마다 `table` 을 나누고 `border-left/right:0`, 블록 상단 `border-top:3px double #000`,
  `margin-top:-1px` 로 이어붙임. (기존 `2편_서식17호` 의 `.noside` 와 같은 계열)

## 3. 인쇄된 작성례(예시값)가 칸 안에 들어 있는 표
- 페이지: `3편_서식10호_..._기록지-1` (17:00 / 17:40 / 김△△ / 50분 / 27,500원 / 박○○)
- 문제: 작성례는 prefill 이므로 CONVENTIONS 상 data-f 대상이지만,
  lint L2 의 MASK 정규식이 한글·단위(분/원)·쉼표를 허용하지 않아 위반이 된다.
- 임시 처리: 예시 글자는 **data-f 밖의 형제 `span.it`** 로 두고, 같은 셀에 빈 `span.cgf` 필드를 둔다.
  칸은 누락되지 않고(GT 유지) 인쇄 예시도 그대로 보인다.
  → 근본 해결은 lint MASK 확장(작성례 패턴) 이지만 lint.py 는 이번 배치에서 수정하지 않음.

## 4. 글머리표만 있고 뒤에 쓸 자리만 비어 있는 줄 (○ / □ 단독)
- 페이지: `1편_서식23호_사업계획서-1~3`
- 문제: 글리프 단독 텍스트 노드는 lint L6(미라벨마커) 에 걸린다. 그러나 실제로는 인쇄 글머리표다.
- 처리: 글머리표를 CSS `::before { content:"○ " }` 로 그린다(텍스트 노드가 아니므로 L6 비대상).
  기록 자리는 그 뒤의 `data-f="textarea"` 로 잡는다.

## 5. 번호 글머리 뒤에 바로 빈칸이 오는 줄 (① ② ③)
- 페이지: `1편_서식1호_..._신청(변경)서-2` (아동수당 지급대상아동이름: ① ② ③)
- 문제: `①<span gp>` 처럼 쓰면 `①` 가 단독 텍스트 노드가 되어 L6 위반.
- 처리: 번호를 한 줄 텍스트로 그대로 두고(`… ① ② ③`), 빈칸은 그 위에
  `position:absolute` 필드 3개로 겹쳐 놓았다.

## 6. 셀 안 점선 구분줄
- 페이지: `1편_서식16_2호-1,4,5`, `1편_서식24호-10`
- 처리: 같은 `td` 안 `div.dtop { border-top:1.2px dotted }` 또는 `tr.dt td{border-top:…dotted}`.

## 7. 서식이 아닌 책 앞붙이 페이지 (음성 앵커)
- 페이지: `1편_서식24호-13, -14, -15, -16~23`
  - 13·15: 완전 백지 → 내용 없는 빈 페이지로 전사 (GT 0)
  - 14: 편 표지(회색 지면 + 흰 카드 + 목차 + 삼각형 모자이크).
    **삼각형 장식은 근사치**(SVG 9개 폴리곤)로만 재현. 원본과 배치가 완전히 같지는 않다.
  - 16~23: 「주요 변경 내용 비교표」 5열(목차/page/2024년/2025년/변경사유) 조밀 표.
    입력 칸 0. 중첩 소표(소득기준표·평가기준표·취약계층표·서식 축소본)까지 전사.
    23쪽의 서식 축소본은 **다른 서식의 그림**이므로 그 안의 □ 에도 data-f 를 붙이지 않았다.
- 판단: 이 페이지들은 코퍼스 분할에서 서식24호 뒤에 붙은 책 앞붙이다. 서식은 아니지만
  "조밀한 표인데 입력 칸은 0" 이라는 가장 값진 음성 앵커라 판단하여 전사했다.

## 8. 기존 위반 1건(내 작업 아님)

# 규약에 없던 패턴 기록 (P6-1 앵커 확장 배치)

`html/CONVENTIONS.md` 로 바로 표현되지 않아 임시 처리한 것들. 규약을 고치지 않고 기존 클래스로 우회했으며,
다음 규약 개정 때 정본에 반영할지 판단할 자료다.

## 1. 작성례(prefill)에 한글이 섞인 칸
- 해당 페이지: `2편_서식23호-1`(미술재활, 언어재활 / 개별서비스 ○명…), `2편_서식9호-1`(OO센터, 언어재활, 매주 화, 금),
  `2편_서식11호-1`(김△△, 50분, 27,500원, 박○○), `2편_서식29호-1`(시·군·구명, 0, –),
  `2편_서식2호` 전 쪽(개인별 성명 전체 명시, 부모급여(현금) 등)
- 문제: CONVENTIONS 는 prefill 을 "인쇄물 포함 전체에 data-f" 라 하지만, 그러면 `lint L2 인쇄글자` 가 걸린다
  (L2 의 MASK 는 ○△0_ 과 숫자·기호만 통과).
- 임시 처리: **작성례 글자는 td 의 인쇄 텍스트로 두고, 같은 td 에 빈 `span.cgf` 를 덮어 칸 전체를 라벨**했다.
  GT 박스는 실제로 사람이 쓰는 영역(칸 전체)을 덮으므로 좌표는 동등하고, L2 를 피한다.
  단 label_stage1 에서는 `placeholder` 가 아니라 `cell` 로 분류된다.
- 예외: 마스킹만 있는 값(`○○○`, `17:00`, `0`)은 규약대로 `<span data-f="…">○○○</span>` 로 직접 라벨했다.

## 2. 목록 글머리 ○ 뒤가 빈 줄인 경우
- 해당 페이지: `2편_서식23호-2`(□ 기타 특기사항 → ○ + 자유기술 영역), `2편_서식27호-1`
- 문제: `lint L6 미라벨마커` 는 텍스트 노드가 정확히 `○` 이고 뒤에 글이 이어지지 않으면 위반으로 본다.
  (기존 `2편_서식22호-1` 이 같은 이유로 위반 1건을 갖고 있다.)
- 임시 처리: 글머리 ○ 를 `.bul::before{content:"○"}` 로 그려 텍스트 노드를 만들지 않았다. 렌더는 동일하고,
  ○ 는 인쇄 장식이므로 GT 에도 영향이 없다.
- 규약 개정안: L6 에서 "뒤에 입력 요소가 이어지는 글머리 ○" 를 예외로 두면 CSS 우회가 불필요해진다.

## 3. O표로 고르는 인쇄 낱말 목록
- 해당 페이지: `2편_서식6호-1`, `3편_서식6호-1`
  (등록(예견) 장애유형 : 시각, 청각, 언어, 지적, 자폐성, 뇌병변(O표) / 장애정도 : 심함, 심하지 않음)
- 문제: 규약의 WORD(글자 택일)는 `^[가-힣A-Za-z]{1,4}$` 라 "심하지 않음" 같은 항목이 걸린다.
  일부만 radio 로 라벨하면 같은 줄에서 라벨/미라벨이 섞여 오라벨이 된다.
- 임시 처리: **그 줄 전체를 인쇄 텍스트로 두었다**(data-f 없음). 실제 입력은 사람이 그리는 동그라미라
  인쇄된 칸이 없고, 1단계 생김새 8종에서 word 는 제외 대상이므로 검출기 학습에는 영향이 없다.

## 4. 달력 칸의 날짜 낱칸
- 해당 페이지: `2편_서식9호-1` (서비스 일정표)
- 각 요일 칸 좌상단에 인쇄된 날짜가 들어 있는 작은 테두리 상자가 있고, 나머지 영역이 자유기술 칸이다.
- 임시 처리: 날짜 상자는 `data-f="date"` + 테두리(34×22px), 칸 나머지는 `position:absolute` 한
  `data-f="textarea"` 로 덮었다. 상자 폭을 34px 로 둔 것은 lint L3(낱칸단독) 의 30px 기준을 넘기기 위한 것이기도 하다.

## 5. 흐름도(처리절차) 도형
- 해당 페이지: `2편_서식2호-14`, `2편_서식12호-1`
- 임시 처리: 12호는 `<div>` 상자 + 화살표 글리프, 14호는 inline SVG(line + marker)로 그렸다. GT 0.

## 6. 원본이 백지/판권지인 쪽
- `3편_서식25호-2`(백지), `3편_서식25호-3`(판권지)
- 그대로 전사했다(GT 0 음성 앵커). 백지 쪽은 높이만 채운 빈 문서다.
